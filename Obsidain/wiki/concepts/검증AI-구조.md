# 검증AI 구조

---

## 정의

생성된 결과물(자소서·공고·코드 등)의 품질을 자동으로 검사하는 AI 레이어.
3단계 D 하이브리드 방식으로 확정.

---

## 확정 구조 — D 하이브리드

```
1차: 룰 기반 검사 (빠름, 비용 0)
        ↓ 통과 실패 시
2차: 영역별 LLM 검증 (Claude)
        ↓ 통과 실패 시
3차: 본인 HITL (Human-In-The-Loop) — 어창선 직접 판단
```

---

## Q7 — 검증 타이밍 (✅ 확정)

| 영역 | 타이밍 | 이유 |
|------|--------|------|
| 자소서 | 실시간 | 사용자 대기 허용, 품질 중요 |
| 면접 답변 | 실시간 | 즉각 피드백 필요 |
| 코드 | 실시간 | 오류 즉시 차단 |
| 공고 수집 | 배치 | 비용↓, 즉시성 불필요 |

---

## Q3 — 검증 실패 처리 (🔲 확정 대기)

### 권장안 (사용자 확인 필요)

| 단계 | 처리 방식 |
|------|----------|
| 실패 발생 | 실패 이유를 프롬프트에 주입 후 **재시도** |
| 3회 초과 | 해당 결과물 **폐기** + 본인(어창선)에게 **알림** |
| 폴백 LLM | **없음** (같은 LLM 재호출) — 폴백은 v2+ 도입 |

> [!note] 결정 대기
> Q3는 아직 사용자 승인 전. 위 권장안 확정 후 이 노트 갱신 필요.

---

## Q5 — 자가업그레이드 (⏳ 다음 차례)

- v1-a: 메모 → 검토 방식 (실패 사례 수동 기록 → 정기 검토)
- v1-b: 실패 패턴 자동 누적 → 룰셋 보강
- v2+: 자동 업그레이드 검토

---

## Q6 — 메타검증 (🔲 완전 미결)

> 검증AI 자체가 틀리면 누가 잡나?

- 현재 결정: **데이터 쌓인 후 결정** (v1에서 강제 설계하지 않음)
- 추후 고려: 검증AI 결과와 HITL 판단의 불일치 패턴 분석

---

## 이 프로젝트에서의 활용

- 자소서 생성 모듈: 2차 LLM 검증 후 3차 HITL
- 공고 수집 모듈: 배치 검증 (1차 룰만으로 충분할 수 있음)
- 코드 생성 모듈: 실시간 1차+2차 검증
