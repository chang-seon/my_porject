# 검증AI — 하네스 엔지니어링 핵심

> LLM이 생성한 결과물(자소서·코드·면접답변·공고 등)의 품질을 자동으로 검사하는 레이어.
> 구조 확정: **D 하이브리드 (계층 + 영역별)**

---

## 검증 구조 (확정)

```
LLM이 결과물 생성
        ↓
┌─────────────────────────────┐
│  1차: 룰 기반 검증           │  ← 본인 룰·체크리스트 / LLM 없음 / 비용 0
│  (빠름, 명확한 규칙 위반 차단) │
└─────────────────────────────┘
        ↓ 통과
┌─────────────────────────────┐
│  2차: 영역별 LLM 검증 (Claude)│
│  ├─ 자소서 검증              │  ← 문체마커·안티패턴·사실여부
│  ├─ 코드 검증                │  ← 오류·보안·스타일
│  ├─ 면접준비 검증            │  ← 논리·일관성
│  └─ 공고탐색 검증            │  ← JSON 형식·필드 누락
└─────────────────────────────┘
        ↓ 통과
┌─────────────────────────────┐
│  3차: 본인 HITL              │  ← 초기=모든 결과 검토 / 후기=자동통과
└─────────────────────────────┘
```

## Q3~Q7 세부 사양 현황

### Q3 — 검증 실패 처리 (✅ 확정 — 2026-05-25)

```
검증 실패 발생
    ↓
실패 이유를 프롬프트에 주입 → 같은 LLM으로 재시도
    ↓
최대 3회 반복
    ↓ 3회 초과
폐기 X
검증 미통과 초안 + 실패 이유 → 본인(어창선)에게 전달
    ↓
본인 판단: [그대로 사용] / [룰셋 수정] / [폐기]
```

- **폴백 LLM**: 없음 (v2+에서 도입 예정)
- **3회로 고정한 이유**: 횟수가 핵심이 아님. 3회 연속 실패 = 프롬프트·룰셋 자체에 문제가 있다는 신호. 더 돌려도 같은 LLM은 같은 실수 반복.
- **배경 원칙**: 자체 LLM이 충분히 학습되기 전까지는 Claude·Gemini가 서로 검증하는 구조로 운영.

### Q5 — 자가업그레이드 (✅ 확정 — 2026-05-25)

**모든 것을 저장하고 학습한다.**

저장 대상:
- 검증 성공한 결과물
- 검증 실패한 결과물 + 실패 이유
- 재시도 과정 전체
- 본인 판단 결과 (사용 / 수정 / 폐기)
- 룰셋 수정 내역
- LLM이 스스로 고친 내용

**배경 원칙**: 외부 LLM(Claude·Gemini)의 실수도 데이터로 쌓인다. 자체 LLM이 모방 학습할 때 "외부 LLM이 틀렸던 패턴"까지 구분할 수 있게 되어, 단순 모방을 넘어 외부 LLM의 실수를 스스로 거를 수 있는 수준으로 성장하는 것이 목표.

### Q6 — 메타검증 (✅ 확정 — 2026-05-25)

> 검증AI 자체가 틀리면 누가 잡나?

탈락 이유를 직접 알 수 없으므로, 간접 신호들을 조합해 추론하는 방식으로 확정.

| 시기 | 방식 |
|------|------|
| v1 초기 | 본인 HITL이 메타검증. 합·탈락 결과 + 본인 판단 확신도 함께 저장 |
| v1 중기 | 데이터 누적 후 통과율 패턴 분석 → 자소서 품질 기준 자동 보정 |
| v2+ | 자체 LLM이 패턴 기반으로 메타검증 인수 |

**메타검증에 활용하는 신호 4가지 (전부 기존 기획 연결)**

| 신호 | 출처 | 연결 |
|------|------|------|
| 합격 패턴과의 거리 | 공개 합격 자소서 비교 | 3-소스 합성 |
| 본인 판단 확신도 | HITL2 판단 시 저장 | 학습 신호 B층 |
| 면접 피드백 역추적 | 면접 준비·회고 ⑨ | 11단계 파이프라인 |
| A/B 테스트 통과율 | 결과 추적 ⑧ | 11단계 파이프라인 |

**배경 원칙**: 탈락 이유를 직접 알 수 없다는 한계를 설계에 정직하게 반영. 이유를 추론하는 게 아니라 "무엇이 효과 있는지"를 간접 신호로 수렴시킨다.
