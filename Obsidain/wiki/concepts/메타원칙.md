# 메타원칙 — 시스템 헌법 (절대 위반 금지)

> 모든 설계 결정은 이 7개 원칙과 충돌하지 않아야 한다.
> 새 기능·설계안을 검토할 때 반드시 이 페이지와 대조할 것.

---

## 7개 원칙

| # | 이름 | 의미 | 실무 적용 |
|---|------|------|----------|
| #20 | 게으름 → 자동화 우선 | 사용자 부담 최소화 | 반복 작업은 무조건 자동화 방향으로 설계 |
| #30 | 초기 학습 → 후기 자동화 | 점진적 자율성 (HITL → 자동) | 처음엔 사람이 검토, 신뢰 쌓이면 자동 전환 |
| #36 | RAG 메타 학습 | 도메인 지식은 RAG로 외부 학습 | 회사 평점컷·면접 기출·산업 트렌드 등을 RAG로 주입 |
| #37 | 동적 기준값 | 하드코딩 금지, DB 기반 자동 갱신 | 임계값·기준값은 코드에 박지 않고 DB에서 읽어옴 |
| #38 | 데이터 격리 + 지식 공유 | 개인=user_id 격리 / 메타=전체 공유 | 내 자소서는 내 것만. 산업 정보는 전체 공유 |
| #39 | 데이터 주권 + 점진 자립 | 로컬 우선, 외부 의존 점진 감소, 비용 최소화 | v1은 로컬 SQLite. 외부 API·LLM 호출 최소화 |
| #50 | Learning to Learn | 외부 LLM이 자체 AI에 학습 방법론까지 전수 | Claude·Gemini가 만든 라벨·패턴을 자체 AI 훈련에 활용 |

## 설계 체크리스트

새 기능을 만들 때 아래를 확인한다.

- [ ] **#20** — 이 기능이 사용자 수작업을 줄이는가?
- [ ] **#30** — 지금은 HITL, 나중에 자동화 전환 경로가 있는가?
- [ ] **#36** — 도메인 지식을 하드코딩하지 않고 RAG로 처리하는가?
- [ ] **#37** — 임계값·기준값이 DB에서 오는가? 코드에 박혀있지 않은가?
- [ ] **#38** — 개인 데이터가 user_id로 격리되어 있는가?
- [ ] **#39** — 로컬에서 동작하는가? 외부 LLM 호출이 최소인가?
- [ ] **#50** — 생성·검증 결과가 라벨로 저장돼 자체 AI 학습에 쓰일 수 있는가?
