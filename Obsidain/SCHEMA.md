# 하네스 엔지니어링 위키 스키마

이 문서는 LLM(Claude Code)이 이 vault를 유지·관리하는 방식을 정의한다.
**LLM이 작업 전 반드시 읽어야 하는 거버넌스 문서다.**

---

## 디렉토리 구조

```
Obsidain/
├── SCHEMA.md          ← 이 파일 (LLM 행동 규칙)
├── raw/               ← 불변 원본 소스 (시나리오, 실험 결과, 회의록, 논문 등)
│   └── .gitkeep
└── wiki/              ← LLM이 작성·유지하는 모든 페이지
    ├── index.md       ← 콘텐츠 카탈로그 (쿼리 시 LLM이 먼저 읽는 파일)
    ├── log.md         ← 시간순 활동 기록 (추가만, 절대 삭제 금지)
    ├── overview.md    ← 프로젝트 전체 합성 요약
    ├── entities/      ← 실체 페이지: AI 모델, 도구, 컴포넌트
    ├── concepts/      ← 개념 페이지: 평가 방법, 지표, 기법
    └── scenarios/     ← 시나리오 페이지: 테스트 케이스 문서
```

---

## 페이지 프론트매터 규칙

모든 wiki/ 페이지는 아래 YAML 프론트매터로 시작한다.

```yaml
---
name: 페이지-slug (kebab-case)
type: entity | concept | scenario | synthesis | source-summary
tags: [태그1, 태그2]
sources: 0          # 이 페이지에 기여한 소스 수
updated: YYYY-MM-DD
---
```

---

## 소스 인제스트 워크플로

새 소스(시나리오, 실험 결과, 아티클 등)를 처리할 때:

1. **소스를 `raw/`에 배치** — 파일명: `YYYY-MM-DD_제목.md` (또는 `.txt`, `.pdf`)
2. **소스 읽기** — 핵심 내용, 수치, 설계 결정 사항 파악
3. **사용자와 핵심 내용 토론** (필요 시)
4. **소스 요약 페이지 작성** — `wiki/` 루트에 `source-summary` 타입으로
5. **관련 entity/concept/scenario 페이지 업데이트** — 새 정보 통합, 기존 주장과 충돌 시 명시
6. **`wiki/index.md` 업데이트** — 새 페이지 등록
7. **`wiki/log.md`에 항목 추가** — 형식: `## [YYYY-MM-DD] ingest | 소스 제목`

---

## 쿼리 워크플로

질문에 답할 때:

1. `wiki/index.md`를 먼저 읽어 관련 페이지 파악
2. 관련 페이지를 읽고 답변 합성
3. 가치 있는 답변(비교 분석, 새 연결)은 wiki 페이지로 저장
4. `wiki/log.md`에 항목 추가 — 형식: `## [YYYY-MM-DD] query | 질문 요약`

---

## 린트 워크플로

"위키 점검" 요청 시:

- 모순된 주장이 있는 페이지 쌍 찾기
- 인바운드 링크가 없는 고아 페이지 찾기
- 언급은 됐지만 페이지가 없는 개념/엔티티 나열
- 새로 조사할 만한 질문 3~5개 제안
- `wiki/log.md`에 항목 추가 — 형식: `## [YYYY-MM-DD] lint | 점검 요약`

---

## 크로스 레퍼런스 규칙

- 위키 내 다른 페이지는 반드시 `[[페이지명]]` Obsidian 링크로 연결
- entity 페이지에서 관련 concept/scenario 링크 필수
- 모순이 발견되면 해당 섹션에 `> [!경고] 모순: ...` 형식으로 명시

---

## 엔티티 타입별 페이지 구조

### entity (AI 모델, 컴포넌트)
```markdown
## 개요
## 주요 특성 / 스펙
## 하네스 평가 결과
## 관련 시나리오
## 참고 소스
```

### concept (평가 지표, 기법)
```markdown
## 정의
## 적용 방법
## 이 프로젝트에서의 활용
## 관련 개념
```

### scenario (테스트 케이스)
```markdown
## 목적
## 입력 / 조건
## 합격 기준 (pass_threshold)
## 실행 결과 이력
## 연관 개념
```

---

## 금지 사항

- `raw/` 파일 수정 금지 (읽기 전용)
- `log.md` 기존 항목 삭제·수정 금지 (append-only)
- 사용자 확인 없이 페이지 삭제 금지
