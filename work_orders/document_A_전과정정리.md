### [세션 1] 개인 에이전트 설계 계획 1

**목적**: Cowork에게 개발 착수 지시용 인수인계 문서 작성

**확정된 것:**
- 프로젝트 정체성: 초개인화 구직 에이전트, v1→v2→v3+ 로드맵
- 메타원칙 7개: #20·#30·#36·#37·#38·#39·#50

- 공고 수집 우선순위: 공식API → Gemini → JSON 표준
- 기능 11단계 파이프라인

  - Git: main(보호)/dev(작업) 분리
- 페르소나 11섹션 + DB 필드 잠정안
- 페르소나 실제 시드값 (어창선 본인 데이터 전체)
- 자소서 생성 정책: "있는 사실 안에서 거짓말"

### [세션 3] 코워크 세션 (현재 채팅방)

**목적**: Obsidian 정리 + Q3~Q6 확정 + 인수인계 v2 작성

#### Q3 확정 과정 (번복 있음)

| 단계 | 내용 |
|------|------|
| 세션1 잠정안 | 3회 초과 시 폐기 + 본인 알림 |
| 세션2 권장안 | 동일 ("3회 초과 시 폐기 + 본인 알림") |
| **코워크 세션 논의** | "3회면 충분한가?" 의문 제기 → 자소서는 100회? 10만 회? 논의 |
| **결론 (번복)** | **폐기 X** → 미통과 초안 + 실패이유 본인 전달 → 본인 판단 [그대로 사용/룰셋 수정/폐기] |
| 배경 | 3회 연속 실패 = 프롬프트·룰셋 자체 문제 신호. 횟수를 늘려도 같은 LLM은 같은 실수 반복 |
| 추가 확정 | 자체 LLM 충분히 학습되기 전까지 Claude·Gemini가 서로 검증 |

#### Q5 확정 과정 (단순화)

| 단계 | 내용 |
|------|------|
| 세션1·2 안 | v1(a)기준메모→본인검토 / v1(b)실패패턴 누적→다음반영 / v2+자동수정(보류) |
| **코워크 세션 논의** | "내가 판단한 것도 LLM이 무조건 학습해야지" |
| **결론 (단순화)** | **모든 것을 저장하고 학습한다** — 성공·실패·재시도 전 과정·본인 판단(확신도)·룰셋 수정·LLM이 스스로 고친 것 전부 |
| 배경 | 외부 LLM 실수도 데이터로 쌓임 → 자체 LLM이 외부 LLM 실수 패턴까지 거를 수 있는 수준으로 성장 |

#### Q6 확정 과정

| 단계 | 내용 |
|------|------|
| 세션2 상태 | 완전 미결. 후보=본인수정/상위메타AI/샘플링감사/HITL의존 |
| **코워크 세션 논의** | "검증AI 자체가 틀리면 누가 잡나?" → 다른 에이전트 개발자들은 어떻게 하는지 확인 |
| **결론** | 간접 신호 4가지 조합으로 확정: ①합격 패턴과의 거리 ②본인 판단 확신도 ③면접 피드백 역추적 ④A/B 테스트 통과율 |
| 단계별 | v1=본인 HITL이 메타검증 / v2+=자체 LLM이 패턴 기반 인수 |
| 배경 | 탈락 이유를 직접 알 수 없다는 한계를 설계에 정직하게 반영 |
