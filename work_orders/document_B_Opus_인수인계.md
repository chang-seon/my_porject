## A. 프로젝트 정체성

자소서·이력서·페르소나를 자동 분석·학습 → 맞는 채용공고 자동 탐색·필터·매칭 → 회사 인재상 맞춤 자소서를 **본인 문체로** 자동 생성 → 면접 준비·회고까지 지원하는 AI 에이전트.

- v1: 어창선 본인 전용 (신입 AI 에이전트 개발자 구직)
- v2: 범용 사용자 확장
- v3+: 거대 에이전트(오케스트레이터 + 전문 에이전트들)의 하위 모듈로 통합

### 핵심 차별점 4가지
1. **본인 문체 학습** — 과거 글에서 문체 마커 추출 → 자소서에 본인 톤 재현
2. **3-소스 합성** — 본인 과거 글 + 공개 합격 자소서(구조만) + 본인 피드백
3. **자체 AI 자립 진화** — 외부 LLM 의존 → 점진적 자체 AI 대체
4. **하네스 엔지니어링** — 다중 검증 레이어 + 재시도 루프 + HITL 안전망

### 통합 대비 3원칙
① 페르소나 외부 분리 저장 ② 기능은 호출 가능 단위로 모듈화 ③ 로그·이벤트 표준 포맷

```
① 자기이해
```

## G. 데이터 전략

### 자소서 학습 — 3-소스 합성
| 소스 | 역할 | 가중치 기준 |
|------|------|-----------|
| 본인 과거 글 | 문체·문장 호흡 | AI 작성 이전 글 위주 |
| 공개 합격 자소서 | 구조·논리 메타패턴 | 표절 금지, 구조만 참고 |
| 본인 피드백 | 승인·수정·거부 신호 | 운영하면서 누적 |

### 시기별 문체 가중치
- α·β (2023) = **높음** (AI 이전, 본인 문체 순도 높음)
- γ (2025) = 중간 (AI 혼합)
- δ (2025~26) = **낮음** (GPT 강함 → 콘텐츠만 활용)

### 3-풀 분리
- **콘텐츠 풀**: 경험·에피소드 (직무별 라벨링 = 미결 M7)
- **구조 풀**: 논리 흐름·단락 패턴
- **문체 풀**: 어휘·리듬·문장 호흡

### 자소서 생성 정책 — "있는 사실 안에서 거짓말"
- ✅ 허용: 콘텐츠 풀에 있는 사실의 윤색·강조·연결·미화·과장
- ❌ 금지: 풀에 없는 사실 창작 (없는 경력·자격·기술·수치)
- 윤색·과장 부분은 HITL2에서 표시 → 승인 후 학습 누적
- 커리어 단계별 톤: 신입=도전·학습·성장 / 주니어=실무·성과 / 경력=수치·리더십

### 데이터 격리·공유 (#38)
- 개인 데이터 (user_id 격리): 페르소나·자소서·풀·지원기록·학습신호·회고·사용자 기준값
- 공유 지식 (전체 공유): RAG 메타·사회통념·산업정보

### 운영 데이터 테이블 (잠정 — 세부는 단계2 확정)
- **패스·배제 기록**: 회사, 직무, 이유, 분석결과, 회사스냅샷, year/month/day
- **학습 신호**: 5층 신호, 라벨 여부, 타임스탬프, 컨텍스트, 수정이력
- **동적 기준값**: domain, context, value, 변경이력
- **공유 지식 (RAG)**: user_id 없음, 전체 공유

### DB 전략
- v1: SQLite 로컬 (외장 SSD/D드라이브 권장, C드라이브 용량 부족)
- v2: PostgreSQL
- 추상화 계층 필수 (SQL 직접 호출 X — 예: `db.get_persona(user_id)`)
- 이전: .db 복사 또는 CSV/JSON export
- LLM 호출부도 추상화 (인터페이스 뒤에 숨겨 자체 AI로 교체 가능하게)

## H. 시스템 아키텍처

### 외부 LLM 역할 분담
- **Gemini**: 웹 탐색·링크 추적 → JSON 변환 → Claude 전달
- **Claude**: 자소서·이력서 생성·검증·분석 핵심
- 둘 다 부트스트랩 도구. 자체 AI 성숙도 따라 점진 대체.

### 공고 데이터 수집 우선순위
1. 공식 API (사람인·워크넷·잡알리오)
2. Gemini 웹탐색 (API 없는 곳)
3. JSON 표준 형식으로 통일 (source 필드로 출처 구분)
- 잡코리아 포함 여부 = 미결 M8

### 외부 API 연동 목록
| 연동 | 용도 | 비고 |
|------|------|------|
| 사람인 API | 공고 수집 | 1순위, 무료 |
| 워크넷 OpenAPI | 공고 수집 | 1순위, 공공 |
| 잡알리오 | 공공기관 공고 | 1순위 |
| Gemini API | 웹탐색·JSON 변환 | API 없는 사이트 |
| Claude API | 생성·검증 핵심 | |
| 텔레그램 Bot API | 알림 | |

> API 키는 protected/에. 절대 코드·로그에 노출 금지. 사용자가 직접 입력.

### 자체 AI 자립 진화 로드맵
| 시점 | 외부 LLM | 자체 AI | 방식 |
|------|---------|--------|------|
| v1 초기 | 100% | 0% | 자체는 관찰·데이터 수집만 |
| v1 후기 | 70~95% | 5~30% | 영역별 부분 자립 |
| v2 | 50% | 50% | 오픈소스 파인튜닝 (Llama·Mistral·Qwen) |
| v3+ | 10% | 90% | 비지도·자기지도 학습 |

**v1부터 반드시 준비**: 라벨여부·타임스탬프·컨텍스트·수정이력 보존.

## I. 검증AI — 확정된 설계 전체

### 구조 — D 하이브리드 (확정)
```
LLM 출력
  ↓
[1차 룰 검증] — 본인 룰·체크리스트, LLM 없음, 비용 0
  ↓ 통과
[2차 영역별 LLM 검증] — Claude
  ├─ 자소서 검증 (문체마커·안티패턴·사실여부)
  ├─ 코드 검증 (오류·보안·스타일)
  ├─ 면접준비 검증 (논리·일관성)
  └─ 공고탐색 검증 (JSON형식·필드누락)
  ↓ 통과
[본인 HITL] — 초기 필수, 후기 자동
```

### Q3~Q7 현황 요약
| Q | 항목 | 상태 |
|---|------|------|
| Q3 | 검증 실패 처리 | ✅ 확정 |
| Q4 | 룰셋·프롬프트 작성 주체 | ⏸️ 단계2 이월 |
| Q5 | 자가업그레이드 | ✅ 확정 |
| Q6 | 메타검증 | ✅ 확정 |
| Q7 | 검증 타이밍 | ✅ 확정 |

### Q3 — 검증 실패 처리 ✅ 확정
```
검증 실패
  → 실패이유 프롬프트 주입 → 같은 LLM 재시도
  → 최대 3회 반복
  → 3회 초과 시:
      폐기 X
      미통과 초안 + 실패이유 → 본인에게 전달
      본인 판단: [그대로 사용] / [룰셋 수정] / [폐기]
폴백 LLM 없음 (v2+에서 도입)
```
배경: 3회 연속 실패 = 프롬프트·룰셋 자체 문제 신호. 횟수를 늘려도 같은 LLM은 같은 실수 반복. 자체 LLM 충분히 학습되기 전까지 Claude·Gemini가 서로 검증.

### Q4 — 룰셋 작성 주체 ⏸️ 단계2 이월
작성 주체(본인 직접 / Claude 초안 / RAG 자동)만 결정할 것. 구체 내용은 단계2에서.

### Q5 — 자가업그레이드 ✅ 확정
**모든 것을 저장하고 학습한다.**
- 저장 대상: 검증 성공·실패·재시도 전 과정·본인 판단(확신도 포함)·룰셋 수정 내역·LLM이 스스로 고친 것
- 배경: 외부 LLM 실수도 데이터로 쌓임 → 자체 LLM이 외부 LLM 실수 패턴까지 학습 → 단순 모방을 넘어 실수를 스스로 거를 수 있는 수준으로 성장

### Q6 — 메타검증 ✅ 확정
탈락 이유를 직접 알 수 없다는 한계를 설계에 정직하게 반영. 이유 추론 대신 간접 신호 4가지로 수렴.

| 신호 | 출처 | 기존 기획 연결 |
|------|------|--------------|
| 합격 패턴과의 거리 | 공개 합격 자소서 비교 | 3-소스 합성 |
| 본인 판단 확신도 | HITL2 판단 시 저장 | 학습 신호 B층 |
| 면접 피드백 역추적 | 면접 준비·회고 ⑪ | 11단계 파이프라인 |
| A/B 테스트 통과율 | 결과 추적 ⑨ | 11단계 파이프라인 |

- v1: 본인 HITL이 메타검증 (Human Spot-check)
- v2+: 자체 LLM이 패턴 기반으로 인수

### Q7 — 검증 타이밍 ✅ 확정
- 자소서·면접·코드 = **실시간**
- 공고 = **배치** (비용↓)

## J. 작동 흐름

### 1단계: 최초 셋업 (처음 1회 + 필요 시 갱신)
```
① 자소서·이력서 파일 첨부 (수동 타이핑 X)
② Claude가 페르소나 11섹션 자동 추출
③ 목표 직무 채팅으로 입력
④ 보강 질문 5~7개 (미결 M5)
⑤ 응답 완료 → 페르소나 확정 · DB 저장
```

### 2단계: 반복 업무 사이클
```
① 공고 탐색·수집 (API + Gemini) → JSON 표준 통일
② 1차 필터링·매칭 (페르소나 제약조건 대조)
③ ✋ HITL1 — 텔레그램 알림 [지원] / [패스] / [보류]
   ↓ 지원                    ↓ 패스 → 패스 처리 흐름
④ 자소서 자동 생성 (3-소스 합성, 문체 마커, 안티패턴 회피)
⑤ 검증AI (1차 룰 + 2차 LLM) → Q3 재시도 루프
⑥ ✋ HITL2 — 본인 자소서 검토 [승인] / [수정] / [폐기]
⑦ 지원 (v1 = 링크 전달)
⑧ 결과 추적 (합격·탈락·미응답)
⑨ 합격 시 면접 준비 + 회고
⑩ 학습 신호 누적 → 다음 사이클 개선
```

### HITL 2지점 — 점진 자동화
| 시기 | HITL1 (지원 결정) | HITL2 (자소서 승인) | 전환 트리거 |
|------|-----------------|-------------------|-----------| 
| 초기 | 모든 공고 본인 직접 | 모든 자소서 본인 직접 | — |
| 중기 | 1차 필터 통과분 일부만 | 검증OK만 본인 | 패스 비율 임계점 |
| 후기 | 자동 (비상 개입) | 자동 (사후 확인) | 검증AI N회 연속 OK (N=미결 M4) |

**선택지 진화:**
- 초기: [지원] / [이번엔 패스] / [앞으로 추천 안 함] / [기타]
- 후기: 자동 필터 후 [지원할까요?] / [더 찾기]

### 패스 처리 흐름
```
[패스] 선택
  → 회사 평판 분석:
     RAG로 규모별 평점컷 자동검색 → 규모별 차등(대/중견/중소/스타트업)
     → Claude 반어법·문맥 이해 → 본인 행동패턴 보정
     → 초기 본인검토, 학습 후 자동
  → 부적합 판정 시:
     - 동일조건 반복 (3일~3개월): 영구 배제
     - 같은 회사 + 다른 부서: 알림 유지
     - 본인 해제 명령: 룰 무효화
     - 취직 후 이직 시: 룰 전체 초기화
```

### 알림 시스템
- 채널: 텔레그램 (단방향 우선, 양방향 = 미결 M9)
- 1차: 조건·자격·마감·경쟁률 (발견 즉시)
- 2차: 회사 상세·평판 (검토 요청 시)
- 3차: 권장 판단 (성숙기 자동)

### RAG 메타 학습 (#36)
- 대상: 회사 평점컷·산업 트렌드·요구 역량·면접 기출·자소서 노하우

- 흐름: RAG 검색 → Claude 종합 → 잠정기준 → 초기 본인 논의 / 후기 자동 적용

### 자체 AI 학습 단계
- v1: 지도학습 (본인 라벨)
- v2: 약지도 (본인 + 검증AI 라벨)
- v3+: 준·자기지도 학습
- **v1부터 반드시 준비**: 라벨여부·타임스탬프·컨텍스트·수정이력 보존

### 자동화 전환 기준 (#30)
- 검증AI N회 연속 OK → 자동화 단계 상승 (N = 미결 M4)
- 패스 비율 임계점 → 필터 자동화
- 본인 최소 승인으로 단계 확정

### 갱신 시계열 (#37)
